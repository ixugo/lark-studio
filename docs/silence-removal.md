# TTS 尾部静音裁剪

vdub 在合并音频段之前自动裁掉 TTS 输出中的尾部静音，
提高调速精度和字幕-音频时间对齐质量。

---

## 问题

TTS 引擎（Edge TTS、OpenAI TTS、CosyVoice 等）生成的音频文件尾部通常附带
100-500ms 的无声段。这些静音在单独播放时不明显，但在字幕流水线中会产生连锁影响：

```
原始字幕时长:       2.5s
TTS 有效语音:       2.3s
TTS 尾部静音:       0.4s
TTS 总时长:         2.7s  ← 超过字幕时长
```

**不裁剪的后果：**

1. **调速偏差** — `adjustAudioSpeeds` 依据 `audioDur / segDur` 计算加速因子。
   尾部静音使 `audioDur` 虚高，导致本不需要加速的音频被不必要地加速，
   或加速倍率超出实际所需。

2. **音质劣化** — 加速倍率越高音质损失越大。静音引起的虚高倍率
   浪费了 `MaxSpeedFactor` 预算，实际有效加速不足。

3. **时间轴间隙异常** — `concatWithTimeline` 按字幕时间轴插入静音段。
   如果音频本身已有尾部静音，拼接后等效于双重静音，
   听感上会出现不自然的长停顿。

---

## 方案

在 `adjustAudioSpeeds` 之前增加 `trimTrailingSilence` 步骤：

```
TTS 输出 → 裁尾部静音 → 调速（如需要）→ 时间轴拼接
```

### ffmpeg silenceremove 滤镜

```
silenceremove=stop_periods=1:stop_threshold=-40dB:stop_duration=0.05
```

| 参数 | 值 | 含义 |
|------|----|------|
| `stop_periods` | 1 | 裁掉尾部 1 个连续静音区域 |
| `stop_threshold` | -40dB | 低于 -40dB 视为静音 |
| `stop_duration` | 0.05 | 静音区域至少持续 50ms 才裁 |

**不影响前部静音和中间停顿**：`start_periods` 默认为 0，不裁前部。

### 安全守卫

裁剪后文件大小必须满足两个条件才替换原文件：

1. 大小 > 0（避免 ffmpeg 产出空文件）
2. 大小 < 原文件（实际发生了裁剪）

不满足条件时保留原文件不变，确保不会因滤镜异常破坏音频。

---

## 阈值选择

**-40dB** 的选择依据：

| 阈值 | 效果 |
|------|------|
| -30dB | 过于激进，可能裁掉低音量的尾音（如气声、辅音释放） |
| -40dB | 平衡点：保留自然尾音，裁掉 TTS 引擎追加的数字静音 |
| -50dB | 过于保守，多数 TTS 静音段在 -45dB 以下但部分低质量音频底噪高于 -50dB |

**50ms** 的 `stop_duration` 确保极短的自然间歇（如音节间微停）不被误裁。

---

## 与调速的配合

裁剪后调速的实际效果：

```
裁剪前:
  TTS 总时长 = 2.7s, 字幕时长 = 2.5s
  factor = 2.7 / 2.5 = 1.08x → 触发调速

裁剪后:
  TTS 有效时长 = 2.3s, 字幕时长 = 2.5s
  factor = 2.3 / 2.5 = 0.92 → 不需要调速
```

多数情况下裁剪后音频时长已小于字幕时长，调速步骤自动跳过，
音质完全无损。

---

## 日志输出

```
[merge] 裁掉 12 段音频尾部静音
```

裁剪数量为实际发生了有效裁剪（文件大小变小）的段数，
未被裁剪的段（无尾部静音或低于阈值）不计入。

---

## 性能

每段音频裁剪为独立的 ffmpeg 调用，处理耗时通常 < 50ms/段。
30 段的典型场景总耗时约 1-2 秒，相比 TTS 生成和字幕烧录可忽略不计。

---

## 配置

当前采用固定参数，无需用户配置。

若未来需要调整阈值，可在 `Pipeline` 配置段扩展
`SilenceThresholdDB` 和 `SilenceMinDuration` 字段。
