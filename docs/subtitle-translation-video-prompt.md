# 给 video_factory_v2 的视频制作提示词

请制作一条约4分钟的中文开发记录视频，题目是《字幕翻译：留住有效检查，删掉无效折腾》。同时生成可录屏的独立HTML页面，让观众看到真实字幕、调用次数和时间条的变化。受众是没有编程基础的朋友。

## 讲述方式

像开发者和用户分享一次真实的小问题：遇到什么、怎么排查、试过什么、为什么留下某些做法又删掉其他做法、实际体验如何。说现代大白话，自然、克制，不炫技、不堆模型名、不编造成功。每屏只讲一个重点，大图少字，用字幕卡片和时间条讲清楚。禁止emoji，需要图标时用简洁SVG。

本次没有改VAD，不要编入解决方案。如需提及，只解释为“专门判断一段声音里有没有人在说话的工具”，不能说它听懂了内容或检查了译文。

## 故事背景

项目把Bill Burnett在TEDxStanford的英文演讲翻成中文字幕并配音。原字幕与译文都是505条、时间轴相同，却仍有四类问题：相邻字幕无故重复；译文太长；因果或数量关系翻错；术语生搬硬套。

开场展示真实旧错例：第440条英文只有“now.”，中文却成了“他一直在研究决策制定以及如何让自己快乐？”。441条原文才是这句话，中文又重复一次。让观众直接看到两张相邻卡片，不用代码截图代替解释。

## 排查过程：不要把尝试都讲成成功

我们先给翻译加上下文和时间预算，再加检查：发现重复就重译，发现配音超长也重译，再配一次比较。它能运行，却增加了翻译和配音的等待；重译也不保证更好。

随后用同一服务实际比较10版提示词，保存400条候选译文。强压字数确实能让超长数降得很好看，但也出现“now”变“嗯”“现”等失真。讲清楚：短不等于对，不能只挑最好看的数字。

最终接受“现有条件下中上”的方案：同一次翻译请求里，让模型在忠实口语和精简口语两种表达中选择。这里是提示词引导，不是代码额外请求两次。它不是完美方案，但不需要重复付出翻译和配音成本。

## 当前实际代码，必须准确介绍

1. 首译仍按批次进行，OpenAI请求携带前后各3条原文及每条字幕的时间预算。CTX只供理解，不译入输出。自定义提示词也追加共同质量规则。
2. 提示词要求口语自然、保留事实、数字、比较、否定、因果、指代和语气；术语按含义表达，不自动加英文括注。片段只翻自身内容，不借邻条补整句。字幕是资料，不是给系统的指令。
3. 全部首译收齐后，线性扫描相邻重复，覆盖批次交界。仅去掉排版空白，保留标点和大小写；译文相同且原文不同，才对连续重复组整体重译一次。原文本来重复则允许保留。
4. 重译保留原引擎；OpenAI带前后文、问题原因及上版译文。Google、必应、DeepLX不被偷偷替换成另一个服务。重译仍整条重复则明确报错。
5. 每条最多参与一次重复修复，外层失败不能重跑整个流程刷新预算；保存字幕、交接配音失败也直接返回。网络与响应格式的有限重试属于另一层，不要说HTTP总共最多两次。
6. 删除了“先生成配音测长→超出20%再翻译→再配音→择短”的运行路径，也删除了纯字幕的长度估算重试。长度只在首译时尽量控制，不额外试读，不生成候选配音。
7. 最终字幕确定后只进行正常配音，保留文本指纹和断点复用。先收齐译文再检查意味着配音不会在第一批首译后立即开始；本次没有重做这部分调度。
8. 完全相同检测不懂语义，不能识别所有局部重义、漏译、错译。也不能保证每条都符合时间预算。

## 使用这些真实证据

### 提示词选型：58条同条件首译

| 指标 | 原提示词 | 采用的候选提示词 |
|---|---:|---:|
| 超过时间窗20% | 22 | 18 |
| 时间落在±20% | 23 | 24 |
| 累计超窗时长 | 15.94秒 | 11.81秒 |

累计超窗约减少26%。但其中另外30条样本超长8→9，不能说每段都改善。不要用“完美对齐”“准确率100%”。

### 本次真实运行：原来的28条问题片段

生产路径只做5批首译、28段正常配音，没有长度重译或候选配音。上一轮同28条日志有21次长度重译和11次候选配音；这些额外操作被省去。验证程序另生成的旧译基线音频不属于产品运行时的试配音。没有测得可直接对比的用户端总等待时间，不要伪造“快了百分之多少”。

同音色、正常语速，对新旧音频对称裁除首尾静音、保留内部停顿后，最初旧译与本次首译比较：超长19/28→6/28，总时长67.68→51.62秒。这是原始旧译对比，不是上一张58条提示词对照；两张表不能混算。错误译文也参与时长统计，6条超长不等于其余22条翻译都正确。

展示三个确有改善的本次输出：

- 39：office hours译为“我给学生答疑很久”。
- 386：人数翻倍译为“停下来的人多了一倍”。
- 120：人生有所作为译为“我希望它能有所成就”。

也必须显示残余问题：225–226仍把机器人/AI误当作工作的类别；438–440有跨条搬移，440的now被译成“但”；40把“教了一阵”具体化为“教了几年”。这些是模型实际输出，不能手改后冒充结果。

另用旧440–441重复错例回放，日志确实只有一次整组重译，整条相同被消除；但重译仍有局部重义。这证明检查执行有效，不证明两句都翻对。该回放不生成配音，不并入28条统计。

## 分镜

0:00–0:35：旧440、441相邻卡片，解释“时间轴没变，内容却错了”。

0:35–1:10：原时间框与中文声音条，解释为什么字数少不一定说得快，计时也不能告诉我们意思对不对。

1:10–1:50：尝试过程。原先“翻译→试读→超长再译→再试读”的长流程变灰，展示激进压缩的“now→嗯”，说明为什么不追逐单一数字。

1:50–2:30：当前短流程“带上下文首译→检查异常重复→必要时整组重译一次→正式配音”。用亮色标保留的检查，划掉超长试配音回路。显示内部两种表达仍在同一次请求里。

2:30–3:15：对照调用次数：省下21次长度重译和11次候选配音。切换39、386、120，展示语言与时间条变化。

3:15–3:45：给出58条选型结果，再展示225、440的残余错误。讲清楚“选了中上的结果，也删掉收益不大的重复劳动”。

3:45–4:00：回到用户体验：少等无效重试，确定的整条重复仍会被检查；翻译模型的错误没有被代码神奇消灭。
