# GitHub 自动更新

Windows 和 macOS 桌面启动时会检查 `ixugo/lark-studio` 的 GitHub 最新正式发布。关于系统页面也可以手动检查。检查使用 GitHub Releases API，读取发布标签、正文和当前平台安装包，不依赖网页结构。

## 提示规则

- 发布、发布修改和所有附件的 `updated_at`/`published_at` 中取最晚时间；距该时间必须超过五分钟才认可。五分钟内、恰好五分钟、未来时间或缺少可用时间均不弹更新窗，自动和手动检查都遵守。等待不会写入忽略版本，手动检查会提示稍后再检查。
- 按三个数字段比较版本，允许前缀 `v` 和前导零。不限制数字段为三位，避免超过 999 后错误排序。
- 自动检查仅在最新发布高于当前版本和忽略版本时提示。
- 手动检查跳过忽略规则；没有更新时显示当前已是最新版本。
- 忽略记录保存在主配置目录的 `update.toml`，设置页保存和主配置热重载不会覆盖它。
- 更新说明按纯文本显示；正文里的 HTML 不会执行。

## 安装流程

更新弹窗显示下载进度条：按安装包已接收字节数推进至 98%，完整下载并通过大小与摘要校验后到 99%；准备安装保持 99%，启动安装辅助进程并进入重启交接时到 100%。下载失败不会显示为完成。

下载匹配平台的发布附件，检查大小和 GitHub 提供的 SHA256 摘要。macOS 使用 DMG 中的完整 `.app`；Windows 使用 ZIP 中的完整应用目录。准备完成后，独立更新进程等待原应用退出、替换安装、重新启动。原安装保留为备份；替换或启动失败时恢复。

默认配置、模型、任务数据库和输出目录保存在应用包外，不属于替换范围。配置、数据库、默认输出目录或模型被自定义到安装目录内时，会拒绝更新并提示先移出数据。Windows 需要从独立的 `lark-studio` 解压目录运行。更新过程中请保持网络连接。无法写入安装位置时，会显示错误。

重启会保留原工作目录及启动参数，并将配置目录转换为绝对路径。辅助进程日志和结果保存在系统用户配置目录的 `lark-studio/updates/run-*/` 中；旧应用保留于安装目录旁的 `.lark-studio-update-*/previous`，用于手动恢复。

如果 GitHub 发布标签与包内程序版本不同，更新记录会绑定实际安装程序的 SHA256，并以已安装发布标签参与版本比较。手动替换程序后校验值失配，旧记录不会继续影响版本判断。发布时仍应保持标签、附件名称和程序版本一致。

自动安装不覆盖 Linux。平台没有对应附件时会显示原因，不能点击立即更新。
